## 1. Invoice PDF — always export a single A4 page

**Commit:** `2117f76`

### Why
`invExportPDF` sliced a tall invoice across multiple A4 pages: it drew the first
page, then appended extra pages by re-drawing the same image at a negative Y
offset. A slightly-too-tall invoice therefore came out as 2 pages with a few
lines orphaned on page 2 — not how an invoice should be sent to a client.

### What changed
`nasama-accounting-v2.invoices.jsx` — the multi-page loop was replaced with a
uniform fit-to-page:

- Compute the full image height in mm from the html2canvas aspect ratio.
- If it exceeds the A4 page height, scale **both** dimensions by
  `pageH / fullHeightMM` so the whole invoice fits on one page.
- Center the scaled image horizontally (`offsetX = (pageW - drawW) / 2`).
- A single `addImage`; `addPage` is gone entirely.

The section comment at the top of the PDF block was updated to match ("jSPDF
fits it onto a SINGLE A4 page (scales down if tall)"), so the file documents the
new behaviour rather than the old one.

### Verification
Headless render of `InvoicePreviewDoc`: a 552 mm invoice (nearly 2× A4) yields
**1 `addImage`, 0 `addPage`, 1 page**, with the aspect ratio preserved.

### Also in this commit
`.gitignore` — added `.firebase/` (Firebase CLI local cache) so deploy artifacts
stop showing up as untracked noise.

## 2. Per-box "Excel" export sign on Dashboard + Performance

**Commit:** `ca2b3fb` · `nasama-accounting-v2.pages.jsx` (+181 / −22)

### Why
Every figure on the Dashboard and Performance pages was read-only on screen.
Getting any of it into a spreadsheet meant retyping. Each box already holds a
clean, already-filtered dataset — it just had no way out.

### What changed
A small green **Excel** button now sits at the top-right of **18 info boxes** —
9 on the Dashboard, 9 on Performance — each exporting that box's underlying data
to a styled `.xlsx`.

**Dashboard:** Cash Flow Trend · Revenue vs Expense · Income YoY · Cash by
Account · Pipeline by Type · Pipeline by Stage · Top Expense Categories ·
Commission Aging · Recent Transactions

**Performance:** Pipeline Funnel · Deal Type Breakdown · Deals per Month ·
Broker Gen vs Retained · Deal Profitability · Developer Performance · Top Deals ·
Expense Control · Broker Performance

Implementation:

- **`xlsxExport(sheetName, filename, aoa, moneyCols)`** — one shared helper.
  Builds the sheet from an array-of-arrays, auto-sizes each column to its longest
  cell (capped at 48 chars), sanitises the sheet name (illegal Excel chars
  stripped, 31-char limit), writes the file, and toasts the row count.
- **`XlsxSignBtn`** — the reusable button (inline SVG download glyph), wired
  through the **existing** `sectionTitle` / `sectionCard` header slots as an
  optional `onExport` arg, so no box layout had to be restructured.
- **Money handling** — amounts are stored as cents/fils internally. `xAED()`
  divides by 100 so cells are emitted as real numbers, and `#,##0.00` is applied
  to the money columns of the data rows. Excel treats them as numbers, not text,
  so they sum and chart correctly.
- **Guards** — missing `XLSX` global → error toast; a box with no data rows →
  "Nothing to export in this box yet" instead of an empty workbook.
- **Filters respected** — exports read the same memoised series the box renders,
  so the active date / year filter is already applied to the output.
- Filenames are dated, e.g. `nasama-cash-flow-2026-07-19.xlsx`.

### Verification
- `pages.jsx` transforms cleanly under the vendored Babel (7.29.7).
- Real `xlsxExport` driven in headless Chrome against the vendored XLSX lib:
  numeric money cells, `#,##0.00` formatting, and the empty-box guard all
  confirmed.

### Notes
Uses the already-vendored `xlsx` 0.18.5 — no new dependency, no CDN, no build
step (consistent with the 2026-07-16 self-hosting work).
